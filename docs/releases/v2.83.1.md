`dot remote prune` no longer reaches outside the host's own folders through a symlink, and leaves another prefix's running verify alone.

### Fixed

- `dot remote prune --yes` could delete a verify ref in a repository outside `git_root` when the repository folder was a symlink or pointed elsewhere through a `.git` link, a `gitdir:` file or a `commondir` file, and could act outside the mirror root when `.dot-remote` was a symlink. It now refuses those with the cause and the next step. (#432)
- When two machines shared one remote account under different prefixes, `dot remote prune --yes` deleted the refs of a verify the other machine was still running. It now leaves a ref while any verify of that checkout runs, whatever its prefix. (#432)
