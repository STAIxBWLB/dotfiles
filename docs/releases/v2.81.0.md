The command names kept for one release after v2.80.0 are gone, `dot sync` stops reading `mirror_path` and refuses to move a destination silently, and `dot apply` replaces a stale workspace link.

### Improved

- `dot sync status` warns when an installed scheduler still calls `dot sync --profile=<store>`, and `dot sync resume` rewrites that job to `--store` before it starts it again. (#407)
- `dot sync push`, `pull` and `fetch` stop before copying anything when a store sets no `target` and its old `mirror_path` names a different folder than the one sync would use. The error names both folders and the `dot sync target` command that picks one. (#409)

### Fixed

- `dot apply` failed with `file exists` when a workspace link pointed at a folder that had moved. It now replaces the stale link, and leaves a link in place with an error when it cannot tell whether its target exists. (#399)

### Action needed

- `dot check`, `dot doctor` and `dot preflight` are removed: use `dot diff --summary`, `dot layouts doctor` and `dot init --detect` (or `dot init --check-only`). (#400)
- `dot ai run` is removed: use `dot admit -- COMMAND [ARGS...]`. (#401)
- `dot ai list`, `dot ai status`, `dot ai rollback` and `dot ai memory|vault|research install|status` are removed: use `dot ai tools list --details`, `dot ai backup status`, `dot ai family rollback` and `dot ai mcp install|status amem|vmem|ares`. (#405)
- `--include-secrets` is removed from `dot backup`, `dot restore` and `dot profile backup|restore`: use `--include-age-key`. (#402)
- The `anchor` skills provider, the `anchor` cask, the `anchor-cli` formula and the skills tools `agents`, `gemini` and `antigravity` are rejected: use `maru`, `maru-workspace`, `maru-cli`, and `claude` or `codex`. A config loaded by v2.80.0 or later was already rewritten. (#404)
- `dot sync --profile` is removed: use `--store`. A scheduled sync installed for a store other than the default keeps failing until it is rewritten, because `dot update` runs the old release and cannot change the job. After upgrading with `dot update` (or `brew upgrade dotfiles`), run `dot sync status --store=<store>`, and if it warns, run `dot sync resume --store=<store>` once. (#407)
- `mirror_path` in `~/.config/dotfiles/config.yaml` and in a workspace store is no longer read. If `dot sync` refuses because the destination would change, run `dot sync target <folder>` with the folder you want. A value that names the same folder sync already uses is dropped from the file on the next save, with a note. (#409)
