`dot` can now install agent-hub, amem and vmem side by side by version and roll them back, and it stops warning about newer amem, vmem, Claude and Codex releases that are still supported.

### New

- `dot ai family install <id> [--version X.Y.Z]` installs ahub, amem or vmem into its own version folder under `~/.local/share/dotfiles/tools/` and points `~/.local/bin/<bin>` at the current one, so sessions running the old version keep working. `dot ai family status` shows the current and previous versions, and `dot ai rollback <id>` switches back to the previous one. It needs npm, runs only when you ask, and leaves an existing `~/.local/bin` link from another install alone unless you pass `--adopt`. (#321)

### Improved

- `dot ai memory status` and `dot ai vault status` accept any amem from 0.14.0 and any vmem from 0.2.1 below 1.0.0, so a newer release such as amem 0.17.0 no longer shows the "not the pinned version" warning. (#320)
- The amem and vmem permissions `dot` grants to Claude and Codex now include the newer tools (`amem_evidence`, `amem_brief`, `amem_correct`, `vmem_skills_mine`), and follow the tool list a release publishes. amem tools that delete, forget, move or purge are never granted. (#320)
- The adaptive permission policy works with any Claude Code from 2.1.283 below 3.0.0 and any Codex from 0.157.1 below 1.0.0, instead of one exact version each. (#320)
- `dot ai update`, `dot apply` and the scheduled update now list the running processes of a tool before replacing it. Nothing is stopped; the list tells you which sessions to restart. (#320)
- The Vault section that `dot ai vault install` writes into your agent instructions now tells agents to find notes with `vmem_search` first and lets them read notes as files. Writes still go only through vmem. (#322)

### Action needed

- After `dot update`, run `dot ai vault install` and then `dot ai agents apply` to pick up the new Vault instructions, and restart agent sessions. (#322)
